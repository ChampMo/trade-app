ต้องคุยกันตรงๆ
ผมไม่ใช่ที่ปรึกษาการลงทุน และนี่คือคำแนะนำเรื่องสถาปัตยกรรม ไม่ใช่คำแนะนำการลงทุน แต่ถ้าจะวางแผนกันจริงต้องเริ่มจากฐานความจริงนี้:
ระบบเทรดอัตโนมัติของรายย่อยส่วนใหญ่ขาดทุน และสาเหตุมักไม่ใช่โค้ดไม่ดี แต่คือ overfit กับ backtest (จูนพารามิเตอร์จนสวยกับอดีต), ต้นทุนกินกำไร (spread + commission + slippage), และ ตลาดเปลี่ยน regime (กลยุทธ์ที่ดีปี 2024 ตายปี 2026)
เรื่อง AI อ่านข่าวโดยเฉพาะ ต้องปรับความคาดหวังก่อน: กว่าข่าวจะขึ้นฟีดฟรี/ราคาถูก แล้ว DeepSeek อ่านจบ (5–30 วินาที) ราคาวิ่งไปแล้ว — คุณจะไม่ชนะเรื่องความเร็ว ไม่ว่าจะเขียนโค้ดดีแค่ไหน กองทุนที่เทรดข่าวจ่ายค่า feed เป็นล้านต่อปีเพื่อวัดกันที่หน่วยมิลลิวินาที
ที่ LLM ช่วยได้จริงและวัดผลได้ คือ 4 อย่างนี้:
บล็อกไม่ให้เทรดรอบข่าวแรง — NFP, FOMC, CPI ไม่ต้องทำนายอะไร แค่ "อย่าถือโพซิชันตอนนั้น" ก็ลด DD ได้ชัด และวัดผลง่ายมาก
จัดหมวด regime — risk-on/risk-off, USD แข็ง/อ่อน ในสเกลวัน–สัปดาห์ ใช้เปิด/ปิด strategy ให้ตรงสภาพตลาด
อ่านโทนแถลงธนาคารกลาง — ประโยคที่เปลี่ยนจาก "patient" เป็น "vigilant" กฎ if-else จับไม่ได้ แต่ LLM จับได้
ตัวคูณขนาดโพซิชัน — เทรดตามสัญญาณเดิม แต่ใส่หนัก/เบาตามความมั่นใจของบริบท
ส่วนที่ทำเงินจริงคือส่วนที่น่าเบื่อ: money management, ต้นทุนต่ำ, ขนาดโพซิชันคงเส้นคงวา, ไม่มีอารมณ์ — และบังเอิญว่านั่นคือสิ่งที่โค้ดทำได้ดีกว่าคนมาก
ผมเลยอยากเสนอให้มองแอปนี้เป็น research platform ก่อน แล้วค่อยเป็นเครื่องทำเงิน คุณค่าที่แท้จริงของมันคือทำให้คุณทดสอบไอเดียได้เร็วและซื่อสัตย์ ถ้าไอเดีย 20 อันแรกไม่รอด แพลตฟอร์มที่ดีจะบอกคุณภายในสัปดาห์ — ไม่ใช่หลังเสียเงินไปแล้ว 6 เดือน แค่นั้นก็คุ้มค่าที่จะสร้างแล้ว
02กฎเหล็ก 7 ข้อ
ข้อจำกัดที่ตัดสินใจครั้งเดียวแล้วห้ามละเมิด — ใส่ไว้ใน CLAUDE.md เพื่อให้ทุก session (และตัวคุณเองตอนตี 2) ยึดเหมือนกัน ถ้าจะละเมิดข้อไหน ต้องแก้เอกสารนี้ก่อน ไม่ใช่แก้โค้ดก่อน
01
AI ไม่เคยส่งออเดอร์
DeepSeek แก้ได้แค่ 3 ค่าที่มีขอบเขตตายตัว — bias (−1…1), size_mult (0…1.5), block (true/false) เพราะ LLM ไม่ deterministic ถ้าปล่อยให้สั่งเทรดตรงๆ คุณจะ backtest ไม่ได้ และจะไม่มีวันรู้ว่ากำไรหรือขาดทุนมาจากกลยุทธ์หรือมาจาก AI
02
Risk Engine คือทางออกเดียวสู่ตลาด
ไม่มี strategy ไหนเรียก order_send เองได้ ทุกตัวส่ง Intent (อยากทำอะไร) แล้ว Risk Engine เป็นคนแปลงเป็นออเดอร์จริงหลังตรวจครบ นี่ทำให้มีที่เดียวที่ต้อง audit และมีที่เดียวที่ต้องเขียนเทสหนักๆ
03
ทุกออเดอร์มี Stop Loss ฝั่งโบรกเสมอ
SL ที่เก็บไว้ในตัวแปร Python ไม่ใช่ SL — มันหายไปพร้อมกับไฟดับ เน็ตหลุด หรือ Windows update รีสตาร์ทเครื่อง ทุก order_send ต้องแนบ sl ไปที่โบรก ถ้าคำนวณ SL ไม่ได้ = ไม่เทรด ข้อนี้สำคัญเป็นพิเศษเพราะคุณรันบนพีซีตัวเอง
04
โค้ด strategy เส้นเดียวกันทั้ง backtest และ live
สาเหตุอันดับหนึ่งที่ backtest สวยแต่ live เจ๊ง คือมันคนละโค้ด on_bar() ตัวเดียวต้องถูกเรียกได้ทั้งจาก backtest engine และจาก live loop ต่างกันแค่ที่ Context ป้อนข้อมูลจากไหนเท่านั้น
05
ทุกการตัดสินใจถูกบันทึกลง SQLite
แท่งเทียนที่เห็น, ค่าอินดิเคเตอร์, prompt และ response ดิบจาก DeepSeek, Intent ที่ออกมา, คำตัดสินของ Risk Engine (พร้อมเหตุผลตอนปฏิเสธ), ผลออเดอร์จริง ไม่มี log = debug ไม่ได้ = ปรับปรุงไม่ได้ = Claude ทำ post-mortem ให้ไม่ได้
06
Kill switch เป็นโค้ด deterministic ไม่ใช่ AI
เงื่อนไขหยุดเป็นตัวเลขล้วน: ขาดทุนเกิน X% ของวัน, drawdown เกิน Y%, ขาดการติดต่อ MT5 เกิน Z วินาที, ออเดอร์ถูก reject ติดกัน N ครั้ง เมื่อทริกเกอร์ → ปิดทุกโพซิชัน หยุดรับ Intent ใหม่ แจ้ง Telegram แล้วรอคนมากดปลดล็อกด้วยมือ
07
Gate ก่อนใส่เงินจริงเป็นตัวเลข ไม่ใช่ความรู้สึก
เขียนเงื่อนไขไว้ตอนที่ยังไม่มีเงินในเกม (คือตอนนี้) แล้วห้ามแก้ตอนที่กำลังตื่นเต้นกับ backtest สวยๆ รายการเต็มอยู่ในหัวข้อ 07
03สถาปัตยกรรม
สี่ชั้น ทิศทางไหลลงทางเดียว และมีคอขวดตรงกลางโดยตั้งใจ
      [svg]
    คอขวดตรงกลางคือของตั้งใจ — ทุกอย่างที่จะกลายเป็นเงินต้องผ่าน Risk Engine ก้อนเดียว ทำให้มีจุดเดียวที่ต้องเทสหนักและ audit ได้
ทำไมต้องแยก Python core ออกจาก UI
UI คุยกับ core ผ่าน HTTP + WebSocket บน localhost เท่านั้น ไม่ใช่ import กันตรงๆ ได้ประโยชน์ 3 อย่าง: ปิดหน้าต่างแอปแล้วบอทยังเทรดต่อ (สำคัญมาก), เปลี่ยน shell จาก Electron เป็น Tauri ทีหลังได้โดยไม่แตะ logic เลย, และวันหนึ่งถ้าย้ายไป VPS ก็แค่ชี้ UI ไปที่ IP นั้น
ข้อควรระวัง — MT4 vs MT5
ใช้ MT5 อย่างเดียว MT5 มี Python package ทางการ (pip install MetaTrader5) ที่คุยกับ terminal ได้ตรงๆ ส่วน MT4 ไม่มี — ต้องเขียน EA ภาษา MQL4 แล้วต่อผ่านไฟล์หรือ socket ซึ่งเปราะและ debug ยากมาก ถ้าโบรกที่คุณอยากใช้มีแต่ MT4 ให้เปลี่ยนโบรก อย่าเปลี่ยนสถาปัตยกรรม
ข้อจำกัดที่ต้องรู้: package นี้รันได้เฉพาะ Windows (ตรงกับเครื่องคุณพอดี), terminal ต้องเปิดค้างและล็อกอินอยู่, และต้องเปิดสวิตช์ Algo Trading ในตัว terminal ไม่งั้น order_send จะถูกปฏิเสธเงียบๆ
เรื่องพีซีหลับ
คุณรันบนเครื่องตัวเอง ซึ่งเวิร์กมากตอนพัฒนา แต่พอมีโพซิชันเปิดอยู่แล้วเครื่อง sleep / เน็ตหลุด / Windows update รีสตาร์ท = คุณมีโพซิชันลอยที่ไม่มีใครดูแล ทางแก้ตามลำดับความสำคัญ: (1) SL อยู่ที่โบรกเสมอ (กฎข้อ 03) นี่คือตาข่ายจริงอันเดียว (2) ปิด sleep/hibernate + ตั้ง Windows update ให้อยู่นอกเวลาตลาด (3) heartbeat ไป Telegram ทุก 15 นาที เงียบเมื่อไรคุณรู้ทันที (4) ตอนขึ้นเงินจริง ย้ายไป Windows VPS (~$15–30/เดือน) ซึ่งจะง่ายมากเพราะสถาปัตยกรรมแยกส่วนไว้แล้ว
04รันหลายกลยุทธ์พร้อมกัน
คุณบอกว่าไม่อยากปิดกั้นสไตล์ไหนเลย — วิธีทำให้ได้แบบนั้นโดยไม่กลายเป็นสปาเกตตี้คือทำ strategy เป็นปลั๊กอินที่มีสัญญาเดียวกันหมด
ทุก strategy ทำแค่หน้าที่เดียว: ดูข้อมูล แล้วบอกว่า "อยากทำอะไร" มันไม่รู้เรื่องขนาดโพซิชัน ไม่รู้เรื่องเงินในบัญชี ไม่รู้ว่ามีเพื่อนกี่ตัวกำลังถือ EURUSD อยู่ — เรื่องพวกนั้นเป็นงานของ Risk Engine
# core/contracts.py
@dataclass(frozen=True)
class Intent:
    symbol:     str
    side:       Side          # LONG | SHORT | FLAT
    confidence: float         # 0..1 — Risk Engine เอาไปคูณ size
    stop_price: float         # บังคับ — ไม่มี stop = ไม่เทรด (กฎ 03)
    take_price: float | None
    reason:     str           # ภาษาคน → ลง journal → Claude อ่านตอน post-mortem
class Strategy(Protocol):
    id:         str           # map เป็น MT5 magic number → แยก PnL ได้สะอาด
    symbols:    list[str]
    timeframe:  TF
    def on_bar(self, ctx: Context) -> Intent | None: ...
Context คือกล่องเดียวที่ strategy มองเห็นโลก — แท่งเทียนย้อนหลัง, อินดิเคเตอร์ที่คำนวณไว้แล้ว, และ ctx.ai (regime/bias ล่าสุดที่ cache ไว้) จุดสำคัญคือ backtest engine กับ live loop ป้อน Context คนละที่มา แต่เรียก on_bar() ตัวเดียวกัน — นี่คือกฎข้อ 04 ที่แปลงเป็นโค้ด
สิ่งที่ได้จากการออกแบบแบบนี้
เพิ่มกลยุทธ์ใหม่ = เพิ่มไฟล์เดียว ไม่ต้องแตะ engine — และนี่คือสิ่งที่ทำให้ Claude ทำงานอัตโนมัติได้ปลอดภัย เพราะขอบเขตของงานชัด
PnL แยกรายกลยุทธ์ได้จริง ผ่าน magic number ใน MT5 → รู้ว่าตัวไหนควรปิด ตัวไหนควรเพิ่มน้ำหนัก

Risk Engine เห็นภาพรวม ถ้า 3 กลยุทธ์อยาก long USD พร้อมกัน มันคือความเสี่ยงก้อนเดียวไม่ใช่สามก้อน — netting ตรงนี้คือสิ่งที่บอทรายย่อยส่วนใหญ่ไม่มี และเป็นสาเหตุที่ระเบิด

3 agent ที่มีหน้าที่ชัด ตารางเวลาชัด และ output ที่ถูกบังคับด้วย schema
Scout
ทุก 15 นาที · โมเดลถูก
ดึงข่าว + ปฏิทินเศรษฐกิจ, ตัดข่าวซ้ำ, แปลงเป็น event object (เวลา, สกุลเงินที่กระทบ, ระดับความแรง) ส่วนใหญ่เป็นงาน parsing ไม่ต้องใช้โมเดลฉลาด
Analyst
ทุก 1 ชม. + เมื่อมีข่าวแรง
อ่าน event ที่ Scout ส่งมา แล้วคืน JSON: regime ปัจจุบัน, bias ต่อ symbol, ช่วงเวลาที่ควร block พร้อมเหตุผลสั้นๆ นี่คือ agent ตัวเดียวที่ส่งผลต่อการเทรด
Reviewer
วันละครั้ง หลังตลาดปิด
อ่าน journal ทั้งวัน สรุปว่าเทรดไหนเสียเพราะอะไร และ bias ที่ Analyst ให้ไว้ตอนเช้าถูกหรือผิด — ข้อนี้ต่างหากที่ทำให้ระบบดีขึ้นตามเวลา
เรื่อง "agent หัวหน้า" ที่คุณคิดไว้
ผมแนะนำให้ หัวหน้าเป็นโค้ด ไม่ใช่ LLM — LLM ที่ทำหน้าที่รวมความเห็นของ LLM ตัวอื่นเพิ่ม latency เพิ่มค่า token และเพิ่มจุดที่มันจะเพี้ยน โดยไม่เพิ่มความแม่นที่วัดได้ ให้ฟังก์ชัน Python ธรรมดารวมผลตามกฎที่คุณอ่านเข้าใจได้ทั้งหมด แล้วเอาความฉลาดของ LLM ไปใช้ตรงจุดที่มันเก่งจริง — คือการอ่านภาษาคน
กติกาบังคับของชั้นนี้
Output เป็น JSON ที่ validate ด้วย Pydantic parse ไม่ผ่าน = ใช้ค่าเดิม ไม่ใช่เดา ไม่ใช่ retry ไม่จำกัด
เก็บ response ดิบทุกครั้งพร้อม timestamp เพื่อให้ replay backtest ได้จริง — นี่คือสิ่งที่ทำให้คุณตอบได้ว่า "ถ้าไม่มี AI layer ปีที่แล้วจะกำไรมากกว่าหรือน้อยกว่า"
Timeout + budget cap ต่อวัน เช่น $2/วัน เกินแล้ว AI layer หลับ ระบบเทรดต่อด้วยกฎล้วน ไม่ใช่หยุดทั้งระบบ
A/B ตั้งแต่วันแรก รันกลยุทธ์เดียวกันสองชุด ชุดหนึ่งเปิด AI ชุดหนึ่งปิด บน demo ถ้าหลัง 3 เดือนชุดที่มี AI ไม่ชนะ ก็ถอด AI ออก — และนั่นคือคำตอบที่มีค่า ไม่ใช่ความล้มเหลว
เรื่องแหล่งข่าว: เริ่มจากปฏิทินเศรษฐกิจ (ForexFactory-style) ก่อนเลย เพราะมันคือ เวลาที่รู้ล่วงหน้า ซึ่งเป็นข้อมูลที่มีค่าที่สุดและถูกที่สุด — ใช้บล็อกการเทรดรอบข่าวได้ทันทีโดยยังไม่ต้องเรียก LLM เลยสักครั้ง แล้วค่อยเพิ่ม RSS ข่าวทีหลัง

PHASE 0พื้นฐานที่ไม่มีใครอยากทำสัปดาห์ 1
เปิดบัญชี demo, ติดตั้ง MT5, ต่อ MetaTrader5 package ให้อ่านราคาได้และส่งออเดอร์ทดสอบได้จริง 1 ไม้ วาง schema SQLite, ตั้งเรโป + CLAUDE.md + BACKLOG.md + CI ที่รัน pytest
เสร็จเมื่อ สคริปต์ 30 บรรทัดเปิดและปิดออเดอร์บน demo ได้ และทุก step ถูกบันทึกลง SQLite
PHASE 1Engine + Riskสัปดาห์ 2–3
Strategy contract, Strategy Runtime, Risk Engine (sizing, daily loss limit, max DD, correlation netting), Kill switch, Execution layer พร้อม retry และบันทึก slippage โหมด paper (จำลองการ fill) กับ demo สลับได้ด้วยสวิตช์เดียว
เสร็จเมื่อ เทส Risk Engine ครบทุกเคสปฏิเสธ และ inject fault แล้ว kill switch ทำงานจริง
PHASE 2Backtest + UI + 2 กลยุทธ์แรกสัปดาห์ 3–5
Backtest engine แบบ event-driven ที่ใช้ on_bar() ตัวเดียวกับ live, UI: รายการกลยุทธ์ + start/stop + equity curve + log สด + ปุ่ม Kill, กลยุทธ์ trend H4 และ mean-reversion M15 ยังไม่มี AI
เสร็จเมื่อ รัน backtest 3 ปี แล้วเอาพารามิเตอร์ชุดเดียวกันไปรัน demo 1 สัปดาห์ ได้พฤติกรรมสอดคล้องกัน
PHASE 3ชั้น AIสัปดาห์ 5–7
ปฏิทินเศรษฐกิจ + news blocking (ทำก่อน ไม่ต้องใช้ LLM), แล้วค่อยต่อ DeepSeek: Scout, Analyst, Reviewer พร้อม Pydantic schema, budget cap, และการเก็บ response ดิบ ตั้ง A/B เปิด/ปิด AI คู่กัน
เสร็จเมื่อ ถอด API key ของ DeepSeek ออกแล้วระบบยังเทรดต่อได้ปกติ
PHASE 4ทำให้ทน + forward testสัปดาห์ 7–10
Watchdog, auto-reconnect, กู้สถานะหลัง crash (ต้องอ่านโพซิชันจริงจาก MT5 ไม่ใช่เชื่อไฟล์ตัวเอง), แจ้งเตือน Telegram, heartbeat แล้วปล่อยรัน demo ยาว โดยห้ามจูนพารามิเตอร์ระหว่างทาง
เสร็จเมื่อ ผ่าน gate ทั้ง 7 ข้อในหัวข้อถัดไป
PHASE 5เงินจริงก้อนเล็กเดือนที่ 4+
0.25% risk ต่อเทรด 1 กลยุทธ์ 1 คู่เงิน 1 เดือน เทียบผลจริงกับ demo ทุกสัปดาห์ ถ้าต่างเกินคาด = กลับไป Phase 4 ไม่ใช่เพิ่มเงิน
เสร็จเมื่อ ผลจริง 1 เดือนสอดคล้องกับ demo ในช่วงเดียวกัน แล้วค่อยขยับขนาดทีละขั้น
PHASE 6ปล่อยให้เดินเองต่อเนื่อง
Claude เหลือบทบาทเดียว: post-mortem รายวัน + เสนอ PR ปรับพารามิเตอร์ ตัวแอปรันเองครบวงจร ย้ายขึ้น VPS ถ้าต้องการ ที่นี่คือจุดที่คำถาม Q2 ของคุณถูกตอบจริง
เสร็จเมื่อ คุณปิดคอมพ์ไป 1 สัปดาห์แล้วกลับมาเจอระบบที่ยังทำงานถูกต้อง
07Gate ก่อนใส่เงินจริง
เขียนไว้ตอนนี้ ตอนที่ยังไม่มีเงินในเกมและยังไม่มีอารมณ์ — แล้วห้ามแก้ตอนกำลังตื่นเต้นกับ backtest สวยๆ ครบทั้ง 7 ข้อถึงจะใส่เงิน
Forward test บน demo แบบไม่แตะพารามิเตอร์เลย — ไม่นับ backtest≥ 90 วัน
จำนวนเทรดจริงต่อกลยุทธ์ที่จะเปิดใช้ — น้อยกว่านี้คือความบังเอิญ ไม่ใช่สถิติ≥ 200 ไม้
Slippage ที่วัดได้จริง เทียบกับที่สมมติไว้ใน backtestต่างไม่เกิน 20%
Max drawdown ที่เกิดขึ้นจริงบน demo เทียบกับที่คุณรับได้≤ ครึ่งหนึ่ง
ทดสอบ kill switch ด้วยการทำให้พังจริง — ถอดสายเน็ต, ปิด terminal ทิ้ง, จำลอง broker rejectผ่าน 3/3
รันผ่านช่วงข่าวแรงจริง (NFP / FOMC / CPI) โดยระบบทำสิ่งที่ตั้งใจไว้≥ 3 ครั้ง
ขนาดความเสี่ยงต่อไม้ในเดือนแรกของเงินจริง — ไม่ว่าผล backtest จะสวยแค่ไหน0.25%
ข้อที่คนพลาดบ่อยที่สุดคือข้อแรก — เพราะมันน่าเบื่อ 90 วันที่ไม่ได้แก้อะไรเลยรู้สึกเหมือนเสียเวลา แต่มันคือช่วงเดียวที่บอกได้ว่าคุณเจอ edge จริงหรือแค่ overfit ระหว่างนั้นคุณไม่ได้ว่างนะ — เอาเวลาไปสร้างกลยุทธ์ตัวที่ 3 กับ 4 ในสาย backtest คู่ขนานไป

เอกสารนี้เป็นคำแนะนำด้านสถาปัตยกรรมซอฟต์แวร์ ไม่ใช่คำแนะนำการลงทุน · การเทรดด้วยเลเวอเรจมีความเสี่ยงที่จะสูญเงินทั้งหมด · ตัวเลขทั้งหมดในหน้านี้เป็นค่าตั้งต้นให้ปรับ ไม่ใช่ค่าที่พิสูจน์แล้ว
