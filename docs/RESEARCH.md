## 2026-09-03 · ema_cross บน EURUSD H4

**ข้อมูล** 20,000 แท่ง H4 จาก XM ครอบคลุม 2013-10 ถึง 2026-09 (เกือบ 13 ปี)
**พารามิเตอร์** EMA 20/50 · stop 1.5×ATR(14) · TP 2R

| | ค่า |
|---|---|
| จำนวนไม้ | 215 |
| ผลรวม | −442.04 (−4.42%) |
| Win rate | 29% |
| Profit factor | 0.77 |
| Max drawdown | 4.43% |
| ต้นทุน spread | 94.67 |
| **ผลก่อนหักต้นทุน** | **−347.37** |
| Monte Carlo p95 DD | 6.45% · โอกาสขาดทุน 100% |

**Walk-forward** train 180 วัน / test 60 วัน / step 60 วัน · ลอง 6 ชุดพารามิเตอร์ต่อหน้าต่าง

| | ค่า |
|---|---|
| จำนวนหน้าต่าง | 75 |
| หน้าต่างที่กำไรนอก sample | 25 จาก 75 |
| **Efficiency** | **0.025** |

**สรุป: ไม่ผ่าน** ถูกปฏิเสธที่ gate แรกด้วยเหตุผล `profit factor: need > 1.0, have 0.769`

**สิ่งที่ได้เรียนรู้** EMA cross ไม่ใช่ edge ตัวมันเองก็ขาดทุนก่อนหักต้นทุนอยู่แล้ว ไม่ใช่กรณีที่ต้นทุนกินกำไร แต่เป็นไอเดียที่ไม่มีขอบตั้งแต่แรก

Walk-forward ตอกย้ำชัดเจน efficiency 0.025 แปลว่าพารามิเตอร์ที่ชนะในช่วงฝึก **แทบไม่เหลืออะไรเลย** ในช่วงถัดไปที่ไม่เคยเห็น และกำไรนอก sample เกิดแค่ 1 ใน 3 ของหน้าต่าง นี่คือหน้าตาของการ overfit ที่แผนเตือนไว้ ถ้าดูแค่ backtest ตัวเดียวจะไม่มีทางเห็น

กลยุทธ์นี้มีไว้เป็นตัวอ้างอิงของสัญญาปลั๊กอิน ไม่ได้มีไว้ทำเงิน

## 2026-09-03 · meanrev_m15 บน EURUSD M15

**ข้อมูล** 30,000 แท่ง M15 จาก XM ครอบคลุม 2025-06 ถึง 2026-09 (ราว 15 เดือน)
**พารามิเตอร์** SMA50 · band 2×ATR(14) · RSI 30/70 · stop 1.5×ATR เลยจุดสุดขั้ว · TP ที่ค่าเฉลี่ย

| | ค่า |
|---|---|
| จำนวนไม้ | 203 |
| ผลรวม | −167.07 (−1.67%) |
| Win rate | 32% |
| Profit factor | 0.89 |
| Max drawdown | 2.98% |
| ต้นทุน spread | 268.57 |
| **ผลก่อนหักต้นทุน** | **+101.50** |
| ต้นทุนคิดเป็น | 19.1% ของกำไรขั้นต้น |
| Monte Carlo p95 DD | 4.37% |

**สรุป: ไม่ผ่าน** profit factor 0.89

**สิ่งที่ได้เรียนรู้ และนี่คือผลที่มีค่าที่สุดจนถึงตอนนี้**

ไอเดียนี้ **มีขอบเล็ก ๆ อยู่จริง** ก่อนหักต้นทุนมันได้กำไร +101.50 แต่ spread กิน 268.57 ทำให้ผลสุดท้ายติดลบ นี่คือกรณีคลาสสิกที่แผนเตือนไว้ว่า "ต้นทุนกินกำไร" และเป็นเหตุผลที่ backtest ที่ไม่คิดต้นทุนอันตรายมาก ถ้าไม่มี cost model กลยุทธ์นี้จะดูเหมือนใช้ได้และผ่านไปถึงขั้น forward test

ทิศทางที่ควรลองต่อ เรียงตามความน่าจะเป็น

1. **ลดจำนวนไม้ ไม่ใช่เพิ่มกำไรต่อไม้** ถ้าไอเดียได้ 101.50 จาก 203 ไม้ แปลว่าได้ราว 0.50 ต่อไม้ ขณะที่ต้นทุนต่อไม้คือ 1.32 ต้องกรองให้เหลือเฉพาะสัญญาณที่ดีที่สุด ไม่ใช่เทรดถี่ขึ้น
2. **ขยับไปกรอบเวลาที่ใหญ่ขึ้น** ต้นทุนต่อไม้คงที่แต่ระยะทางที่คาดหวังโตตามกรอบเวลา M15 คือกรอบที่ต้นทุนหนักที่สุดเมื่อเทียบกับการเคลื่อนไหว
3. **บัญชีที่ spread ต่ำกว่า** XM Standard คิด spread 20 จุด บัญชีแบบ raw spread บวก commission อาจถูกกว่าถ้าเทรดถี่ ตัวเลขนี้ทดสอบได้ด้วย `--spread` และ `--commission`

ข้อสังเกตอีกอย่าง `duplicate_position` ถูกปฏิเสธ 185 ครั้ง แปลว่ากลยุทธ์ส่งสัญญาณซ้ำขณะที่ยังถือไม้เดิมอยู่บ่อยมาก ไม่ใช่ปัญหา แต่บอกว่าสัญญาณเกิดเป็นกลุ่ม ๆ

## หมายเหตุด้านเครื่องมือ

Backtest เร็วขึ้น 8 เท่า (10.0 วิ → 1.3 วิ ต่อ 2,000 แท่ง) หลังแก้สองจุด คือแคช peak/day-start equity ไว้ในหน่วยความจำแทนการอ่าน SQLite ทุก tick และลดความถี่ reconcile ในโหมด backtest จากทุกแท่งเหลือวันละครั้งตามเวลาจำลอง ทำให้ walk-forward 75 หน้าต่าง × 6 พารามิเตอร์ รันจบในไม่กี่นาทีแทนที่จะเกินชั่วโมง

## สิ่งที่ยังไม่ได้ทดสอบ

- รันสองกลยุทธ์พร้อมกันเพื่อดูว่า netting กับ equity curve รวมดีขึ้นไหม
- กรอบเวลา H1 และ D1
- ผลของการบล็อกช่วงข่าว ซึ่งยังไม่มีปฏิทินเศรษฐกิจ (Phase 3)

## ตั้งแต่ 2026-09-03 ทุก backtest ถูกเก็บไว้

`python -m tradeapp backtest` บันทึกผลลงตาราง `backtests` ในเจอร์นัลทุกครั้ง (ปิดด้วย `--no-save`) เก็บสถิติ ต้นทุน
walk-forward, Monte Carlo, gates และไม้ที่ปิดแล้วทุกไม้ แต่ **ไม่เก็บ equity curve** เพราะเป็นจุดต่อแท่งและไม่มีรายงานไหนใช้

- ดูรายการ: `python -m tradeapp report runs`
- เทียบของจริงกับ backtest: `python -m tradeapp report drift --strategy ema_cross --days 30`

รันแรกที่เก็บไว้คือ **#1 ema_cross EURUSD H4** 215 ไม้ net -442.04 ซึ่งเป็นตัวเลขเดียวกับที่บันทึกไว้ข้างบน เก็บไว้เพื่อให้
รายงาน drift มีของให้เทียบเมื่อเริ่มเทรดจริง ตอนนี้ยังไม่มีไม้จริง รายงานจึงบอกตรง ๆ ว่ายังเทียบอะไรไม่ได้

## 2026-09-03 · exit management บน ema_cross

รันบนข้อมูลชุดเดิม EURUSD H4 19,900 แท่ง ต้นทุนจริงของ XM ทุกตัวเหมือนกันหมด ต่างกันแค่การจัดการไม้หลังเปิด

| ตัวแปร | net | win rate | PF | maxDD | avg hold |
|---|---|---|---|---|---|
| ไม่จัดการเลย (ของเดิม) | −442.04 | 28.8% | 0.77 | 4.43% | 69.2h |
| break-even ที่ 1R (+20 จุด) | −364.19 | **37.2%** | 0.78 | 3.65% | 63.8h |
| ATR trail 2.5× | **−333.33** | 28.8% | **0.80** | **3.38%** | 62.4h |
| ATR trail 3.5× | −375.79 | 28.8% | 0.80 | 3.77% | 67.8h |

สิ่งที่อ่านได้จากตารางนี้

1. **การจัดการไม้ช่วยจริง แต่ไม่ได้สร้าง edge** ทุกตัวยัง PF < 1.0 คือยังขาดทุนหมด กลไกใหม่ทำให้ขาดทุนน้อยลงและ drawdown ตื้นขึ้น แต่กลยุทธ์ที่ไม่มี edge ก็ยังไม่มีอยู่ดี ตรงกับที่คาด และเป็นเหตุผลที่ยังไม่มีตัวไหนควรถูก promote
2. **break-even ดัน win rate ขึ้นเยอะ (28.8% → 37.2%) แต่ PF แทบไม่ขยับ (0.77 → 0.78)** ซึ่งเป็นภาพคลาสสิกของการตัดไม้ที่กำลังจะกำไรทิ้ง ชนะบ่อยขึ้นแต่ชนะน้อยลงต่อครั้ง **ห้ามอ่าน win rate ตัวเดียวแล้วสรุปว่าดีขึ้น**
3. **ATR trail 2.5× ให้ผลดีที่สุดในสามตัว** และที่ 3.5× แย่ลง แปลว่ามีจุดที่เหมาะสมอยู่ระหว่างนั้น ซึ่งเป็นสัญญาณอันตรายของการ fit เข้ากับอดีต ถ้าจะใช้ค่าไหนจริงต้องผ่าน walk-forward ก่อน ไม่ใช่เลือกจากตารางนี้

ค่าเริ่มต้นของ ema_cross ยังปิดการจัดการไม้ทั้งหมด (`break_even_r=0`, `trail_atr_mult=0`) ตารางนี้จึงไม่เปลี่ยนผลของรันเดิมที่เก็บไว้ การเปิดใช้จริงคือการเปลี่ยนพารามิเตอร์ ซึ่งตามบันได lifecycle ต้องเตะกลับไปขั้น research แล้วพิสูจน์ใหม่ทั้งชุด

เจ้าของถามว่าเทรด M1 ได้ไหม ดึงข้อมูลจริงมา 50,000 แท่ง (2026-07-16 → 2026-09-03 ประมาณเจ็ดสัปดาห์)
แล้วรันทั้งสองกลยุทธ์บน M1 ด้วยต้นทุนจริงของ XM

|---|---|---|
| จำนวนไม้ | 153 | 326 |
| **กำไรก่อนหักต้นทุน** | **+342.99** | **+266.51** |
| ต้นทุน spread | −849.16 | −2,426.14 |
| ผลจริง | −506.17 (−5.06%) | **−2,159.63 (−21.60%)** |

| **ต้นทุนคิดเป็นสัดส่วนของกำไรดิบ** | **104.3%** | **296.6%** |

อ่านสองบรรทัดนี้คู่กัน: **ทั้งสองไอเดียมีขอบเป็นบวกก่อนหักต้นทุน** (+342.99 และ +266.51) แล้ว **spread กินหมดแล้วกินเกิน**
ema_cross จ่ายค่า spread เกือบสามเท่าของกำไรดิบทั้งหมดที่หามาได้ และทำ drawdown 21.66% ในเจ็ดสัปดาห์ ซึ่งเกือบชนลิมิต 30%
ที่จะสั่ง kill switch ตัดทั้งระบบ

เทียบกับไทม์เฟรมยาวขึ้นบนข้อมูลเดียวกัน (คนละช่วง แต่ต้นทุนเดียวกัน) — ยิ่งแท่งสั้น ต้นทุนยิ่งกินสัดส่วนมากขึ้นชัดเจน

| ไทม์เฟรม | ต้นทุนต่อกำไรดิบ |
|---|---|
| H4 (ema_cross) | 6.4% |
| M15 (meanrev) | 264% |
| M1 (meanrev) | 104% |
| M1 (ema_cross) | 297% |

**ข้อสรุป: M1 บนบัญชี XM Standard ที่ spread 20 จุด ไม่มีทางเป็นบวก** ไม่ใช่เพราะไอเดียแย่ แต่เพราะระยะที่ราคาวิ่งต่อแท่ง
เล็กเกินกว่าจะจ่ายค่าผ่านทางไหว ถ้าจะเอา M1 จริง ๆ ต้องเปลี่ยนบัญชีเป็นแบบ raw spread ที่ spread ต่ำกว่ามาก แล้วรันตารางนี้ใหม่
ก่อนตัดสินใจ ไม่ใช่เปิดให้บอทเทรดแล้วค่อยดู
